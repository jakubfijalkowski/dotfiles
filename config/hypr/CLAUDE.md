# Hyprland configuration

Personal [Hyprland] config in a dotfiles repo (`config/hypr`), on Arch Linux.
Always tracks the **latest** Hyprland — never write back-compat shims or pin to a
version.

## Read the docs first (every time, before editing)

This file deliberately does **not** document Hyprland or its config API — those
change with every release. Read the sources of truth first, and re-check them
whenever you touch something:

1. **The `hl` Lua API** comes from the local stubs at
   `/usr/share/hypr/stubs/hl.meta.lua` (autogenerated for the installed version).
   Confirm every function, field, and table shape there — never guess. If this
   file and the stubs ever disagree, the stubs win. `.luarc.json` wires
   lua-language-server to these stubs.
2. **Hyprland behaviour, options, dispatchers, and rules** come from the wiki:
   <https://wiki.hypr.land/Configuring/>. Consult it before changing any
   semantics.

## This is the Lua config, not hyprlang

Everything is Lua through the global `hl` table — no `key = value` / `source = …`
hyprlang syntax, and no `hyprland.conf` for the compositor. `hyprland.lua` is the
entrypoint and `require`s the modules below:

| Module | Holds |
|---|---|
| `conf/colors.lua` | Catppuccin Mocha palette. **Pure data module** — returns a table and calls no `hl.*`; others pull it via `local colors = require("conf/colors")`. |
| `conf/monitors.lua` | env, monitor layout, workspace→monitor binding |
| `conf/input.lua` | keyboard & mouse |
| `conf/looknfeel.lua` | general / decoration / group / dwindle / master / misc + animations |
| `conf/windowrule.lua` | window & workspace rules, app tags |
| `conf/keybindings.lua` | keybinds |
| `conf/autostart.lua` | startup programs |

## Hyprland ecosystem tools

`hypridle.conf`, `hyprlock.conf`, and `xdph.conf` configure other Hyprland
ecosystem tools (hypridle, hyprlock, xdg-desktop-portal-hyprland) and are managed
in this repo too. Each uses its own config format — consult that tool's own docs.

## Deployment

`~/.config/hypr/` is built from symlinks **into this repo** (`conf` is a directory
symlink; `hyprland.lua` is the active entrypoint symlink), so editing repo files
edits the live config. Hyprland reloads on save; `hyprctl reload` forces it.
Confirm a change is live with `hyprctl getoption <opt>`.

## Formatting & validation

- **stylua** enforces style via `.stylua.toml` (2-space indent, 100 columns,
  double quotes, Unix) — identical to nvim's. stylua is **not on `PATH`**; use the
  mason binary: `~/.local/share/nvim/mason/bin/stylua hyprland.lua conf/*.lua`.
  Run it before committing.
- Syntax-check with `luac -p <file>`.

## Repo conventions

- Commits are **GPG-signed** — a commit may block on a pinentry passphrase prompt
  that only the user can answer.
